# Part A — dodder-hyphen semantics (fully specified; execute now)

## Task A1: The `dodder-hyphen` interpreter builtin

**Files:** `internal/cutting_garden_plugins/tag_interpreter.go` (+ its `_test.go`).

**Approach:** add `dodderHyphenTagInterpreter struct{}` implementing `TagInterpreter` per RFC 0019 §6/§7, and register it in `tagInterpreterRegistry` under `"dodder-hyphen"`. Semantics (verbatim from the RFC — read §6 for the normative text):
- `Normalize` — identity (`_` literal, no lift, §7). `SortKey` — plain lexical (a leading `_`/`_ ` sorts high naturally, §7).
- `Buckets(tags, namespace)`:
  - empty namespace → WHOLE-DIMENSION: one membership per distinct tag, `Bucket == Via == tag` (same as naive).
  - non-empty namespace `N` → NAMESPACE ROLLUP: for each tag that is `N` or `N-<rest>`, bucket by the IMMEDIATE next segment (`Bucket == "-"+<immediate segment after N>`, per D4's continuation form; `Via ==` the producing tag). Tags not under `N` contribute nothing. Deduplicate by `Bucket` per node (a coalesced bucket's `Via` is any one contributor).
- `Matches(tags, term)` — TRANSITIVE: true iff `term` equals a tag OR is a segment-prefix of some tag (`project` matches `project-client-acme`; segment boundary is `-`, so `pro` does NOT match `project`).
- `Complete(tags, op, bucket)` — at a rollup bucket `-<seg>` under namespace `N`, `TagAdd` appends the namespace tag `N-<seg>` (the only unambiguous leaf the rollup names, RFC 0019 §6.2); `TagRemove` drops every tag under `N-<seg>`. At a whole-dimension bucket (a full tag), add/remove that exact tag (naive-like). Set semantics (idempotent).

**TDD** (mirror the RFC §6 testing table, and `tag_interpreter_test.go`'s naive cases): rollup + `Via` (`project` over `project-cutting_garden`/`project-client-acme`/`project-client-baxter` → buckets `-cutting_garden`, `-client`; `-client` coalesces acme+baxter); transitive `Matches`; `Complete` at `-client` appends `project-client`; `_` literal; empty-namespace whole-dimension parity with naive.

## Task A4: Bare-tag trellis terms → `Matches`

**Files:** `internal/trellis_eval/eval.go` + `validate.go` (+ tests); read the current bare-identifier-term deferral first.

**Approach:** un-defer the bare-identifier tag term in the evaluator (per FDR 0025 §Bare-tag): when a query term is a bare tag (not `field=value`, not `!type`), evaluate it by finding the node's tag dimension(s) and calling the resolved interpreter's `Matches(nodeTags, term)`. The evaluator must be given the interpreter-resolution context (the plugin's tag-field declarations + the config override) — thread it in the same way the facet/field evaluation already gets plugin context. naive `Matches` (exact) keeps the current effective behavior for a naive dimension; dodder-hyphen `Matches` (transitive) is the new capability. Pin: `-query 'project'` matches a task tagged `project-client-acme` under a dodder-hyphen dimension, exact-only under naive. **Investigate first** how much plugin/interpreter context the evaluator currently has — if threading it is large, this task may split.

# Part B — namespace grouping UI (needs a design pass BEFORE planning)

Part B is the organize GROUPING surface for hierarchies. Its semantics are specified (Task A1's `Buckets`/`Complete`), but the **CLI + document-dialect surface has open decisions** that should be settled (a short design pass / your call) before writing bite-sized tasks:

- **OPEN — namespace group-by spelling.** How does `organize --group-by <?>` select "the `categories` dimension, namespace `project`" vs a facet dimension? Options: (a) explicit `--group-by categories/project` (path form; `/` is unused — **recommended**, unambiguous, reads as a path); (b) bare `--group-by project` resolved by trying it as a tag-namespace of the (single) tag dimension (terser, ambiguous with a facet named `project`, and undefined for multiple tag dimensions); (c) `--group-by categories:project` (collides with the date `:granularity` suffix). Recommend (a).
- **OPEN — continuation-heading document dialect (D4 = decision A, no `=`).** Slice 1/2 render tag buckets as `## =<tag>`. D4 says a namespace rollup renders `## -client` (no `=`) and a flat tag renders bare (`## work`, quoted `## "_ inbox"`). This changes the organize document GRAMMAR for tag dimensions: `generate.go` (`dimensionSections`), `document.go` parse (`isValueTerm`/`isDimTerm`/`parseBody`), and `memberships()`/`assignments()` must learn the no-`=` tag spelling AND round-trip it. Pin the exact heading grammar (does the dimension heading `# categories=` stay, or is it hoisted away per the UAT note?) before implementing — the parser and the apply id-resolution both depend on it.
- **Rollup write-back** (Complete at `-client` → `project-client`) is specified (A1) but its APPLY wiring reuses Slice 2's membership path; the only new piece is the namespace-aware `planMemberships` call (buckets are namespace rollups, not whole tags). Small once the dialect is settled.

**Recommended sequencing:** execute Part A now (it is fully specified and delivers config-selected dodder-hyphen matching + the interpreter itself), then settle Part B's two OPEN decisions in a short design pass and plan Part B as its own file.
